# Requirements: Bible Word Study Tool

## Requirement 1: Word Study Input

### User Story
As a Bible student, I want to enter an English word and its Strong's concordance number so that I can begin a structured word study.

### Acceptance Criteria
1. The study input form displays a text input for the English word and a text input for the Strong's number
2. The Strong's number field validates against the pattern `/^[GH]\d+$/` (e.g., "G25", "H157")
3. Both fields must be filled before the form can be submitted
4. On submission, the system fetches the Strong's concordance data for the entered number
5. Invalid Strong's number format shows an inline validation error without making an API call

### Correctness Properties
- Property: For any string matching `/^[GH]\d+$/`, `validateStrongsNumber` returns `true`; for any string not matching the pattern, it returns `false`
- Property: For any Strong's number starting with 'H', `getTestament` returns `'OT'`; for any starting with 'G', it returns `'NT'`

---

## Requirement 2: Strong's Concordance and Lexicon Lookup

### User Story
As a Bible student, I want to see the Strong's concordance definition, original Hebrew/Greek word, transliteration, and lexicon entry so that I can understand the word's original language meaning.

### Acceptance Criteria
1. The system retrieves the Strong's definition from the pre-loaded StrongsData DynamoDB table
2. The system retrieves the extended lexicon entry for the same Strong's number
3. The display shows: Strong's number, Strong's definition, original word (Hebrew or Greek), transliteration, and lexicon entry
4. Definition and lexicon are fetched in parallel for performance
5. If the Strong's definition is not available, the system displays "Definition not available"
6. If the lexicon entry is not available, the system displays "Lexicon entry not available"
7. The system also fetches and displays the English dictionary definition of the entered word

### Correctness Properties
- Property: For any Strong's number matching `/^[GH]\d+$/`, `getStrongsStudyData` returns an object where `definition`, `originalWord`, `transliteration`, and `lexiconEntry` are all non-empty strings (either real data or fallback messages)
- Property: `fetchEnglishDefinition` never throws — for any non-empty string input, it returns a non-empty string

---

## Requirement 3: Cross-Reference Locations

### User Story
As a Bible student, I want to see all the Bible verse locations where the same Strong's number is used so that I can study how the word is used across Scripture.

### Acceptance Criteria
1. The system retrieves all cross-reference verse locations for the Strong's number from the StrongsData table
2. Cross-references display verse locations only (e.g., "Romans 5:8") — no copyrighted Bible text is served
3. Cross-references are listed in canonical Bible order
4. Each cross-reference has a text area where the user can record their observations after looking up the verse in their own Bible
5. If no cross-references are found, the system displays "No cross-references found for this Strong's number"

### Correctness Properties
- Property: For any valid Strong's number, `getCrossReferences` returns an array where every element has a non-empty `reference` string and an initially empty `notes` string

---

## Requirement 4: Personal Notes

### User Story
As a Bible student, I want to add personal notes throughout the word study — both for individual cross-references and as general observations — so that I can capture my insights.

### Acceptance Criteria
1. Each cross-reference location has its own text area for per-reference notes
2. The worksheet includes a general notes text area for overall observations
3. All notes (per-reference and general) are saved as part of the word study entry when the worksheet is saved
4. Notes are restored when a saved study is reopened
5. Notes support multi-line text input

---

## Requirement 5: AI Study Summary

### User Story
As a Bible student, I want an AI-generated summary that synthesizes all my word study data — including my cross-reference observations — so that I can see the key insights in one concise paragraph.

### Acceptance Criteria
1. After working through the study steps, the user can click an "AI Summary" button to generate a synthesis
2. The AI summary is generated by Amazon Bedrock (Claude 3 Haiku) using the Strong's data, lexicon entry, English definition, user's cross-reference observations, and general notes
3. The summary is 3-5 sentences focusing on the word's original language meaning and how cross-references illuminate its usage
4. The generated summary is stored as part of the word study entry
5. If Bedrock is unavailable, the system displays "AI summary unavailable. Please try again later."
6. The core word study functionality works fully without the AI summary — it is an optional enhancement

### Correctness Properties
- Property: `generateStudySummary` never throws — for any `WordStudyEntry` with at minimum `word`, `strongsNumber`, and `strongsDefinition` populated, it returns a non-empty string (either the summary or the fallback message)

---

## Requirement 6: Save and Resume Studies

### User Story
As a Bible student, I want to save my word study worksheets and come back to them later so that I can build a library of studies over time.

### Acceptance Criteria
1. The user can save a word study worksheet at any point (in-progress or completed)
2. Saved studies are stored in DynamoDB keyed by an anonymous user ID
3. The user can view a list of their saved studies showing word, Strong's number, date, and status
4. The user can open a saved study to view or continue editing
5. The user can delete a saved study
6. Studies are sorted by most recently updated

### Correctness Properties
- Property: For any valid `StudyWorksheet`, `saveWordStudy` followed by a get with the returned `studyId` returns a record where `wordStudies` and `status` match the saved input
- Property: For any `StudyWorksheet` with a non-empty `createdAt`, saving preserves the original `createdAt` value while updating `updatedAt` to the current timestamp

---

## Requirement 7: Anonymous User Identity

### User Story
As a user, I want the app to remember my studies without requiring me to create an account so that I can start using the tool immediately.

### Acceptance Criteria
1. On first visit, the app generates a unique anonymous user ID and stores it in localStorage
2. On subsequent visits, the app retrieves the existing user ID from localStorage
3. All API calls include the user ID to scope data access
4. No personally identifiable information is collected or stored

---

## Requirement 8: API Security and Throttling

### User Story
As a system operator, I want the API to be protected from abuse so that the service remains available and costs stay controlled.

### Acceptance Criteria
1. API Gateway has a usage plan with throttling (100 req/s burst, 50 req/s sustained)
2. Lambda functions use least-privilege IAM roles scoped to specific DynamoDB tables and the Bedrock model
3. CORS is configured to allow only the CloudFront domain
4. All traffic is served over HTTPS
5. DynamoDB encryption at rest is enabled
6. Bedrock prompts contain only Strong's concordance data and user study notes — no copyrighted text
